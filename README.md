# SGWT-GAT: спектральные графовые вейвлеты для предсказания белок-белковых взаимодействий

Код и данные к статье **В.Д. Антонов, А.А. Кочкаров. «Применение спектральных графовых вейвлетов для предсказания белок-белковых взаимодействий»**, XXVIII конференция «Нейроинформатика-2026» (МФТИ).

> **In English.** Code for SGWT-GAT: the spectral graph wavelet transform (Hammond et al., 2011) is used as a fixed multi-scale feature extractor in front of a GAT encoder for protein–protein interaction (link) prediction on SHS27k. The repository also contains a controlled comparison of band-pass spectral wavelets with HyboWaveNet-style low-pass random-walk diffusion.

## О работе

Графовые сети GCN и GAT агрегируют признаки белка только по ближайшим соседям, а сети белок-белковых взаимодействий (PPI) устроены на нескольких масштабах: комплексы, модули, хабы. В SGWT-GAT перед энкодером GAT добавлен блок спектрального графового вейвлет-преобразования (SGWT). Он описывает, чем признаки белка отличаются от его сетевого окружения разного радиуса.

Основные результаты на SHS27k (7 типов взаимодействий × 10 seed):

- SGWT-GAT значимо превосходит базовую модель PlainGAT: средний ROC-AUC 0,906 → 0,930 (p = 1,1·10⁻⁶), AP 0,904 → 0,934 (p = 5,5·10⁻⁷);
- частота «коллапса классов» при фиксированном пороге снижается с 77 до 54 % запусков;
- спектральные (полосовые) вейвлеты и диффузия в духе HyboWaveNet (низкочастотный фильтр) оба лучше базовой модели, но ни один не доминирует: они комплементарны по типам взаимодействий.

## Метод

Для каждого типа взаимодействия строится граф по обучающим рёбрам и его нормированный лапласиан $L = I - D^{-1/2} A D^{-1/2}$. К каждому столбцу матрицы признаков $X$ применяются фильтры

$$
X_{\mathrm{SGWT}} = \left[\, X \;\Vert\; h(L)X \;\Vert\; g(t_1 L)X \;\Vert\; \dots \;\Vert\; g(t_4 L)X \,\right],
\qquad h(\lambda) = e^{-\lambda},\quad g(\lambda) = \lambda e^{-\lambda},
$$

с масштабами $t \in \{0{,}5;\ 1;\ 2;\ 4\}$. Операторы $g(tL)$ и $h(L)$ приближаются рядами Чебышёва порядка $K = 5$ на $[0;\ 2]$, без вычисления собственных векторов. Из 50 признаков белка получается 300. Блок вычисляется один раз и не обучается.

Схема модели:

```
X (N×50) → SGWT-блок (N×300, не обучается) → LayerNorm + Linear (300→64)
         → 2 × GATConv (4 головы → 1, d = 64)
         → декодер: MLP([z_u ‖ z_v ‖ |z_u − z_v| ‖ z_u ⊙ z_v]) → p(u, v)
```

Базовая модель PlainGAT — та же сеть без SGWT-блока и входной проекции: признаки подаются сразу на вход GAT.

## Структура репозитория

```
.
├── train.py               # один запуск: тип взаимодействия × режим признаков × seed
├── analyze.py             # сводка по results.csv: средние, тесты Уилкоксона, коллапс
├── sgwt_ppi/
│   ├── data.py            # загрузка SHS27k, разбиение рёбер, режимы --neg-mode
│   └── models.py          # SpectralGraphWavelet, RandomWalkDiffusion, UnifiedGNN
├── data/ppi/              # SHS27k: признаки белков и списки рёбер по типам
├── results/paper/         # сырые результаты запусков из статьи и их сводки
├── 00_check_legacy.bat … 04_analyze.bat   # серии запусков (Windows)
└── requirements.txt
```

Режимы признаков (`--feature-mode`):

| Режим | Что подаётся на вход энкодера |
|---|---|
| `none` | исходные признаки X (базовая модель PlainGAT) |
| `spectral` | SGWT-признаки (предлагаемый метод, SGWT-GAT) |
| `diffusion` | $[X \Vert PX \Vert P^2X \Vert P^3X \Vert P^4X]$, $P = D^{-1}(A + I)$ — диффузия в духе HyboWaveNet |
| `proj` | X через те же LayerNorm + Linear, что у `spectral` и `diffusion`, без многомасштабных признаков (контроль) |

Энкодер выбирается флагом `--encoder`: `gat` (по умолчанию, используется в статье), `gcn`, `sage`, `gin`.

## Установка

Нужен Python 3 (код проверен на 3.13). Сначала установите PyTorch под вашу версию CUDA по инструкции с [pytorch.org](https://pytorch.org/get-started/locally/), затем остальные зависимости:

```bash
pip install -r requirements.txt
```

Эксперименты статьи проводились на NVIDIA GeForce RTX 5070 Ti (PyTorch 2.x, CUDA 12.8, PyTorch Geometric). Один запуск занимает 20–30 с на GPU. На CPU (флаг `--cpu`) код тоже работает, но во много раз медленнее.

## Данные

В `data/ppi/` лежит SHS27k (Chen et al., 2019) в версии репозитория [GNN-PPI](https://github.com/ZJUDataIntelligence/GNN-PPI) (Zhou et al., 2022), на котором основан этот код: 1690 белков, 50-мерные признаки белков (`features_SHS27.npy`) и отдельный список рёбер для каждого из 7 типов взаимодействий (`SHS27_<тип>.txt`, одна пара индексов белков на строку).

| Тип | reaction | binding | ptmod | activation | inhibition | catalysis | expression |
|---|---|---|---|---|---|---|---|
| Уникальных рёбер | 3164 | 4017 | 1303 | 3297 | 1407 | 3492 | 687 |

Рёбра каждого типа делятся на обучение / валидацию / тест в пропорции 85 / 5 / 10 % (`--split-seed`, по умолчанию 1234). Граф для SGWT и передачи сообщений строится только по обучающим рёбрам. Отрицательные примеры — пары белков без известной связи; в валидации и тесте их столько же, сколько положительных.

## Запуск

Один запуск:

```bash
python train.py --ppimode reaction --feature-mode spectral --seed 1
```

Каждый запуск дописывает строку с метриками (ROC-AUC, AP, accuracy, precision, recall, F1 при пороге 0,35, P@K и R@K для K = 50, 100) в `results/results.csv`. Тестовые метрики берутся на эпохе с лучшим валидационным ROC-AUC. Флаг `--skip-existing` пропускает уже посчитанные запуски.

Серия «3 режима × 7 типов × 10 seed» (Linux / macOS):

```bash
for t in reaction binding ptmod activation inhibition catalysis expression; do
  for s in $(seq 1 10); do
    for f in none diffusion spectral; do
      python train.py --neg-mode clean --feature-mode $f --ppimode $t --seed $s --skip-existing
    done
  done
done
python analyze.py --neg-mode clean
```

На Windows те же серии запускаются файлами `01_main_clean.bat` (основная серия), `02_proj_control.bat` (контроль `proj`) и `04_analyze.bat` (сводка).

`analyze.py` печатает и сохраняет в `results/summary_<neg-mode>.md` средние ROC-AUC и AP по типам, парные сравнения режимов (односторонний тест Уилкоксона) и число запусков с коллапсом классов (F1 < 0,01).

Обучение: Adam, шаг 10⁻², без L2-регуляризации, бинарная кросс-энтропия, ранняя остановка по валидационному ROC-AUC с терпением 100 эпох (максимум 1000).

## Протокол отрицательных примеров: `legacy` и `clean`

Флаг `--neg-mode` задаёт, какие пары попадают в обучающие отрицательные примеры:

- **`legacy`** — протокол исходного кода GNN-PPI / HGCN, на котором получены результаты статьи. В обучающие отрицательные примеры попадают все несвязанные пары, включая валидационные и тестовые, а также валидационные и тестовые положительные рёбра с меткой 0.
- **`clean`** (по умолчанию) — ни одна валидационная или тестовая пара не попадает в обучение.

Обе модели в статье обучались в одинаковых условиях, поэтому их сравнение корректно, но абсолютные значения метрик зависят от протокола. Для новых экспериментов рекомендуется `clean`.

Чтобы воспроизвести результаты статьи, используйте `--neg-mode legacy`:

```bash
python train.py --neg-mode legacy --ppimode reaction --feature-mode spectral --seed 1
```

При `legacy` разбиение рёбер совпадает с использованным в статье. Точного совпадения метрик не будет: вычисления на GPU недетерминированы, ROC-AUC отличается в пределах ~0,01. Быстрая проверка на 8 запусках — `00_check_legacy.bat`.

### Сырые результаты статьи

В `results/paper/` лежат результаты всех запусков, на которых построены таблицы статьи, в формате `results.csv`:

| Файл | Что внутри |
|---|---|
| `sgwt_vs_plaingat_140runs.csv` | PlainGAT (`none`) и SGWT-GAT (`spectral`), 7 типов × 10 seed — табл. 1 статьи и коллапс классов |
| `three_modes_210runs.csv` | `none`, `diffusion`, `spectral`, 7 типов × 10 seed — сравнение спектральных вейвлетов с диффузией |
| `summary_140runs.md`, `summary_210runs.md` | сводки `analyze.py` по этим файлам |

Запуски выполнены исходным кодом проекта по протоколу `legacy` (`split_seed` = 1234). В серии на 140 запусков удалён один повторный запуск (reaction, PlainGAT, seed 1); оставлен последний, как в анализе статьи. Сводки пересчитываются так:

```bash
python analyze.py --csv results/paper/sgwt_vs_plaingat_140runs.csv --neg-mode legacy
python analyze.py --csv results/paper/three_modes_210runs.csv --neg-mode legacy
```
